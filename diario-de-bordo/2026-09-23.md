### Senha nunca pode ficar salva do jeito que a pessoa digitou. O bcrypt transforma ela num hash que só serve para comparar, nunca para descobrir a senha original de volta.

### Quando a tabela já existe com o formato antigo, o CREATE TABLE IF NOT EXISTS não aplica a trava nova. É preciso apagar o banco e deixar ele nascer de novo com a regra atualizada.

### Comparar a senha só quando o usuário existe deixa a resposta mais rápida nesse caso e mais lenta quando não existe, e um atacante consegue medir esse tempo para descobrir quais e-mails estão cadastrados. Comparar sempre com um hash, mesmo que falso, fecha essa brecha.

### O token JWT funciona como um crachá assinado: carrega quem é o usuário e até quando vale, e qualquer tentativa de alterar o conteúdo quebra a assinatura e derruba o token.
