# Diário de bordo: 14/10/2026

**Tema:** Estado e componentes no React: lista de tarefas e formulário controlado  
**Módulo:** Front-end (React)

## O que aprendi

- Para atualizar a lista no useState, o setter recebe uma função: setTarefas(listaAtual => [...listaAtual, novaTarefa]). O React nunca deve ter o array alterado direto; o spread (...) cria uma cópia nova com o item a mais, e é isso que faz a tela redesenhar.
- Para alterar um item da lista, usei o .map(): se o id bate, devolvo uma cópia do objeto com o campo trocado ({ ...tarefa, concluida: !tarefa.concluida }), e os outros itens voltam iguais. Para remover, o .filter() guarda só quem tem id diferente do removido.
- Formulário controlado: o input tem value={novoTitulo} e onChange que chama o setNovoTitulo. Assim o React é a fonte da verdade do que está digitado, e limpar o campo depois de adicionar é só fazer setNovoTitulo(''). O evento.preventDefault() no submit evita que a página recarregue.
- Quando o código tem erro de sintaxe (como setTarefas{...} no lugar de setTarefas(...)), o Vite não compila e a tela fica em branco. O erro aparece no terminal do pnpm dev e no console do navegador (F12).
- Valor derivado não precisa de useState. O total de pendentes é só tarefas.filter(t => !t.concluida).length, calculado a cada renderização a partir da lista. Guardar isso em outro estado criaria dois valores que podem ficar fora de sincronia.
- Renderização condicional com ternário: {todasConcluidas ? 'mensagem' : totalPendentes}. O && do meio da constante existe porque uma lista vazia também tem 0 pendentes, então só "0 pendentes" não basta para dizer que tudo foi concluído.
- Separar em componente: o Tarefa.jsx recebe tarefa, onAlterar e onRemover por props. O componente só mostra e avisa o que aconteceu; quem altera a lista continua sendo o App, que é dono do estado.
- Um select controlado funciona igual ao input: value={categoria} e onChange com setCategoria. A categoria escolhida entra no objeto da nova tarefa.
