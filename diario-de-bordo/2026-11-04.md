# Aula 09 — Banco de dados em nuvem com Turso e libSQL (04/11/2026)

## ✅ O que eu aprendi

- Quando o sistema vai para a internet, o servidor apaga os arquivos dele toda vez que é atualizado. Se o banco continuasse sendo um arquivo, todos os usuários e tarefas sumiriam a cada atualização.
- Por isso o banco foi para a nuvem, no Turso. O servidor só manda e busca os dados lá, e eles ficam guardados mesmo se o servidor for apagado.
- O endereço e a senha do banco ficam num arquivo `.env`, que não vai para o GitHub. Assim ninguém vê a senha do meu banco.
- Se o `.env` não existir, o sistema continua funcionando com um arquivo na minha máquina.

## 🧩 Principal dificuldade

O sistema continuava salvando na minha máquina, mesmo com o `.env` pronto com o endereço e a senha do Turso.

## 🔧 Como eu resolvi

O `.env` tinha sido salvo com uma marca invisível no começo (BOM), e por isso o servidor não conseguia ler o arquivo. Salvei de novo como UTF-8 normal, sem BOM, e o servidor passou a usar a nuvem. Agora ele também avisa quando o arquivo está salvo do jeito errado.

## 💡 Observações

Outros problemas que apareceram nesta aula:

| Problema | Por que aconteceu | Como resolvi |
| --- | --- | --- |
| Erro 404 ao conectar no Turso | endereço com `/` no final ou senha copiada pela metade | copiar o endereço e a senha inteiros |
| Editar uma tarefa que não existe deixava a tela esperando para sempre | o código da aula não respondia nada nesse caso | responder "tarefa não encontrada" |
| O terminal dizia "Turso", mas os dados iam para a minha máquina | um servidor antigo ainda estava ligado na mesma porta | desligar o servidor antigo; agora o sistema avisa quando a porta está ocupada |

## As 11 lacunas

| Lacuna | O que fiz | O que acontecia sem ela |
| --- | --- | --- |
| 1 | Troquei a biblioteca do banco antigo pela do Turso | o servidor nem ligava |
| 2 | Fiz o servidor ler o arquivo `.env` e avisar se ele foi salvo do jeito errado | o sistema nunca achava o banco na nuvem |
| 3 | Criei as variáveis que dizem se vamos usar a nuvem ou o arquivo local | as outras partes do código davam erro |
| 4 | Criei a conexão com o banco | nenhuma tela conseguia salvar ou buscar dados |
| 5 | Fiz o terminal mostrar onde os dados estão sendo salvos | eu não sabia se estava salvando na nuvem ou na minha máquina |
| 6 | Escrevi os comandos que criam as tabelas de usuários e de tarefas | não tinha tabela para criar |
| 7 | Fiz o banco criar as tabelas e o usuário admin quando o sistema liga | dava erro de "tabela não existe" em tudo |
| 8 | Criei funções prontas para buscar, salvar e apagar dados | as rotas de tarefas chamavam funções que não existiam |
| 9 | Refiz as rotas de cadastro, login e verificação do servidor | ninguém conseguia criar conta nem entrar |
| 10 | Coloquei de volta a parte que entrega a tela do site (da aula passada) | o servidor dava erro ao ligar e a tela não abria |
| 11 | Fiz o servidor só abrir depois que o banco está pronto | alguém podia usar o sistema antes das tabelas existirem |

## Perguntas da aula

**Por que trocamos de banco?**

> O banco antigo só sabia salvar num arquivo da máquina, e na nuvem esse arquivo é apagado a cada atualização. O Turso guarda os dados na internet, então eles não somem.

**O que mudou por ser assíncrono?**

> Antes o banco estava no mesmo computador e respondia na hora. Agora ele está na internet e demora um pouco, então o código precisa esperar a resposta antes de continuar. Por isso as rotas ganharam o `await`, que quer dizer "espera o banco responder".

**Para que serve o `db.batch()`?**

> Para mandar vários comandos de uma vez com segurança. Se eu mandar dois comandos juntos do jeito comum, o Turso faz só o primeiro e ignora o segundo sem avisar. Testei e só uma tabela foi criada. Com o `batch`, ele faz todos, ou nenhum se der problema.

## Como configurei o Turso

1. Criei a conta no site do Turso usando o GitHub.
2. Criei um banco chamado `dsw`, em São Paulo.
3. Pelo terminal, gerei o arquivo `.env` com o endereço e a senha do banco.
4. Testei: criei uma tarefa, desliguei o servidor, apaguei o arquivo local e liguei de novo. A tarefa continuou lá, porque estava na nuvem.
