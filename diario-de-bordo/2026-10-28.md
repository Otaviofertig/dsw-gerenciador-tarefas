## O que aprendi

- Com o Tailwind, o visual muda só trocando classes no JSX. Para deixar o botão do login verde, troquei `bg-blue-600` por `bg-emerald-600` e o hover por `hover:bg-emerald-500`, sem tocar em nenhum arquivo `.css`.
- O estado inicial do `useState<Prioridade>` define o que o formulário mostra ao abrir. Mudei de `"medium"` para `"high"`, e o texto do botão de "Adicionar" para "Nova Tarefa".
- Lacuna 1: `listarTarefas` não fazia a requisição. Faltava `const res = await fetch(url, { headers: authHeaders() })`. O `authHeaders()` coloca o `Authorization: Bearer <token>`, e sem ele a API responde 401.
- Lacuna 2: a função `criar` deixava criar tarefa em branco. Adicionei `if (tituloLimpo.length < 3) { setErro("..."); return; }`. O `trim()` vem antes, para espaços não contarem como letras, e o `return` impede de seguir para o `fetch`. O servidor também valida, mas a tela responde na hora.
- Lacuna 3: o botão "Não tem conta? Registre-se" fica dentro do `<form>`, e um `<button>` sem `type` vale `submit`, então recarregava a página. Com `type="button"` ele só executa o `onClick`.
- Um comentário `{/* ... */}` não pode ficar entre os atributos de uma tag JSX (dentro do `<button ...>`). Só entre elementos. Isso quebrava a tela, e a correção foi mover o comentário.
- `node_modules` não vai junto quando se copia ou renomeia uma pasta. Erros como `'tsx' não é reconhecido` e `'vite' não é reconhecido` se resolvem com `npm install` (ou `pnpm install`) na pasta do projeto.
- `localhost:5173` (Vite) lê o código ao vivo e mostra a mudança ao salvar. `localhost:3000` (Express) entrega o `dist`, que é um build antigo até rodar o build de novo. Foi por isso que minhas mudanças "não apareciam" quando abri a porta 3000.
- O `web/index.html` tinha sido trocado por uma cópia do `dist/index.html`, apontando para `/assets/index-xxxx.js`, e o build falhava com `Failed to resolve`. A fonte precisa apontar para `/src/main.tsx`. A pasta `dist` é gerada e nunca deve ser copiada nem editada.
- `.gitignore` não aceita espaço antes do padrão: com `" node_modules/"` o Git lê o espaço como parte do nome e não ignora nada.
- `npm audit` apontou uma vulnerabilidade alta no `body-parser` (usado pelo Express). `npm audit fix`, sem `--force`, resolve, e um `npm install` seguinte já a corrigiu.
- Para subir back e front em um terminal só, usei o pacote `concurrently` com o script `dev:all`.
- Para levar o projeto para este repositório, o back (`gerenciador-tarefas/api`) e o front (`app-react/web`) ficam em pastas diferentes. O `FRONT_DIST` do `server.ts` deixou de ser `./web/dist` e passou a ser `../../app-react/web/dist`, senão o Express não acha o build.
- O `tsconfig` do repositório usa `verbatimModuleSyntax`, que exige `import { type Request }` para tipos. Sem isso o `tsc` dá o erro TS1484.
- O pnpm bloqueia scripts de instalação por segurança (`ERR_PNPM_IGNORED_BUILDS`). Para liberar `esbuild` e `better-sqlite3`, criei um `pnpm-workspace.yaml` com `allowBuilds`.
- Antes de apagar um clone, conferi com `git status` e com os commits não enviados que não havia nada meu nele. Só a cópia local foi apagada.

## Perguntas do laboratório

**A.** O que acontece na tela do React se tentarmos usar uma variável comum em vez do `useState` para guardar dados que devem aparecer na interface?

> A tela não atualiza. A variável muda na memória, mas o React não sabe que precisa desenhar de novo. O `useState` avisa o React a cada mudança, e aí ele redesenha a tela com o valor novo.

**B.** Por que o formulário do Login recarregava a página inteira, e como o `type="button"` resolveu esse problema?

> O botão de trocar de modo está dentro do `<form>`, e todo `<button>` sem `type` age como botão de enviar. Então clicar nele enviava o formulário e o navegador recarregava a página, apagando o estado. Com `type="button"` ele deixa de enviar o formulário e só executa o `onClick`.

**C.** Qual a principal vantagem de usar o Tailwind em vez de um arquivo `.css` tradicional?

> O estilo fica junto do elemento, então para mudar a aparência eu só troco a classe, sem procurar em outro arquivo. Foi o que fiz com o botão: troquei `bg-blue-600` por `bg-emerald-600` e a cor mudou na hora.
